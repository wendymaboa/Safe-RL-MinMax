Safe RLHF via Minmax Penalties:
Value-Function-Derived Safety Signals for LLM Fine-Tuning

Can the agent's own value function replace KL penalties and learned cost models as the safety signal in PPO-based LLM fine-tuning?

The Problem

RLHF makes LLMs helpful. It doesn't guarantee they're safe.

Training doesn't erase the risk

RLHF is the standard way to align LLMs with human intent — and it works well for helpfulness.

But safety training doesn't generalise as robustly as capability does: aligned models remain vulnerable to producing harmful content across BeaverTails' 14 harm categories, to reward hacking against imperfect proxy rewards, and to deceptive alignment, where a model appears compliant while pursuing misaligned goals internally.

The question isn't whether RLHF can be made safer — it's whether it can be done without adding a second model, more annotation, or another hyperparameter to tune.

So the field patches it

Two mechanisms dominate: anchor the policy, or add a second model to police it.

KL penalty
Anchors the policy to a frozen reference model during PPO training, discouraging it from drifting into reward-hacked or degenerate behaviour. Standard since Ziegler et al. and InstructGPT.
RRLHF(s,a) = rφ(s,a) − β·KL[πθ(·|s) ‖ πref(·|s)]
Distinct from PPO's own clipped surrogate objective, which is a training-stability trust region, not a safety mechanism.
Learned cost model
Safe RLHF and HC-RLHF train a separate model on human harmlessness labels, then balance it against the helpfulness reward via a Lagrange multiplier.
maxπ JR(π)   s.t.   JC(π) ≤ d

The central question

Can we replace KL penalties and learned cost models with a safety signal that already exists inside the agent's own value function — no new model, no new annotation, no new hyperparameter?

Our Idea

ROSARL: let the critic's own value estimates supply the safety penalty — no auxiliary model required.

The value function already knows

ROSARL tracks the best and worst values the agent has encountered, and turns the gap between them into the penalty.

Rmin ← min(Rmin, rt)    Rmax ← max(Rmax, rt)
Vmin ← min(Vmin, Rmin, V(st))    Vmax ← max(Vmax, Rmax, V(st))
Runsafe = Vmin − Vmax   (guaranteed ≤ 0)

When the unsafe-state detector fires, the reward is replaced with Runsafe — the worst value any reachable state could plausibly take, given everything the agent has seen so far.

It gets stricter on its own

Vmax — rises toward the best value seen
Vmin — falls toward the worst value seen
Runsafe = Vmin − Vmax — grows more negative automatically

No manual severity tuning: the penalty calibrates itself purely from the agent's own training trajectory.

Algorithm 1 — the LLM adaptation

for each training step t: x ~ X_train ; y ~ πθ(·|x) δt ← Detoxify(y) # toxicity score rt ← 1 − 2·δt # centered reward ∈ [−1,1] Vt ← Vψ(x,y) # critic value estimate update Rmin,Rmax,Vmin,Vmax if δt > τ: # unsafe state detected rt ← Vmin − Vmax update πθ, Vψ via PPO with rt, KL anchor β
  • Reward centered to [−1,1], not raw −δ — gives Vmax a genuine positive anchor (original ROSARL has a dense, bipolar task reward independent of the detector; ours doesn't).
  • Terminal-token value estimate, not averaged across the sequence — matches the single terminal reward structure.
  • Small KL anchor β retained purely to prevent mode collapse — not a safety-specific hyperparameter.

Two phases, one mechanism

Only the source of the unsafe-state signal zt changes. Algorithm 1 and the PPO loop stay identical.

Phase 1 — Detoxify
Scores the generated response y, returns toxicity δt ∈ [0,1]. Fast, reproducible, no training required. The focus of this proposal's empirical evaluation.
Phase 2 — activation probe
Fires on internal activations before the output token is produced. Targets categories surface-level classifiers miss — most notably self-harm.

Three Hypotheses

Each maps to one dimension of the ablation design: the mechanism, the detector, and the extension to activation-level detection.

H1 — Mechanism

H1

A policy trained with the Minmax penalty produces fewer harmful outputs than one trained with KL divergence alone, measured by harm rate on BeaverTails-Evaluation.

Expected to persist across base models (GPT-2 small, Qwen 1–3B) and fine-tuning strategies (full FT, LoRA) — isolating the mechanism as the source of any benefit, not a model-specific property.

H2 — Detector quality bounds coverage

H2

Harm reduction is bounded by the recall of the unsafe-state detector. Categories where Detoxify's signal is weak or absent — self-harm, most notably — are not expected to improve, and may regress.

Algorithm 1 only acts when zt = 1. This frames detector quality, not the penalty mechanism itself, as the primary variable modulating coverage — and it's the most defensible, most interesting hypothesis in this proposal.

H3 — Consequence of H2

H3

If H2 holds, replacing Detoxify with an activation-level probe should extend coverage to categories where Detoxify's recall is near zero — without altering the Minmax mechanism itself.

The penalty is held fixed; only the source of zt varies. Any change in coverage is attributable to the detector, not to a different safety algorithm. Connects directly to Cintas et al. and Rateike et al.'s activation-probing work.

The Plan

Method, evaluation, ablations, limitations, and the timeline for getting there.

Data and models

  • BeaverTails — 27,186-prompt training split; 700-prompt held-out BeaverTails-Evaluation, 14 harm categories, shared with Safe RLHF and HC-RLHF for direct comparison.
  • Base models — GPT-2 small (117M, hardware-feasible) and a Qwen model in the 1–3B range (cluster-dependent).
  • Fine-tuning strategies — full fine-tuning and LoRA, compared directly in Ablation 3.
  • HarmBench — 500+ adversarial behaviours, used as the out-of-distribution robustness check via attack success rate.

How we'll know it worked

  • Harm rate (all & non-empty) — the primary metric; non-empty is treated as primary since empty generations trivially register as non-toxic.
  • Response diversity — unique responses / total prompts. Guards against a policy gaming harm rate by converging on a small set of low-information outputs.
  • Attack success rate — HarmBench, the stronger out-of-distribution test of H1.
  • Mean reward — reported for completeness only. KL and Minmax optimise different reward functions, so it's not used for cross-condition comparison.

What could go wrong

  • Hardware — GTX 750 Ti, 2GB VRAM, Windows. Scoped honestly to GPT-2 small locally; Qwen and extended runs depend on cluster access.
  • Detector-bounded coverage — Algorithm 1 only acts when the detector fires. Categories Detoxify can't see (self-harm) can't be improved in Phase 1, regardless of RL tuning.
  • PPO / critic-dependence — Algorithm 1 needs a learned critic for V(st). This is a real scope boundary against GRPO-style, critic-free approaches, which are increasingly common in recent RLHF/RLVR work.
  • Benchmark coverage — BeaverTails and HarmBench cover naturalistic and adversarial harm, but not truthfulness or long-horizon manipulation.

Thank you

A value-function-derived safety signal, requiring no auxiliary model, no extra annotation, and no new safety-specific hyperparameters — and a two-phase design honest about exactly where its coverage ends and Phase 2 begins.
